## Description

<!-- What does this MR do and why? Jira: DVRS-XXXX -->

Replaces every raw technical error string in the chat UI (HTTP status codes, "HTTP error! status: 4xx", "Stream dropped mid-response", "Rate limited.") with jargon-free, actionable messages. Users now see clear explanations and a concrete next step for every failure mode: agent unreachable, session expired (401), rate limited (429), and stream dropped mid-response.

## Changes

- `utils/errorHandler.ts` — Add `ErrorHandler.fromRawMessage()` that parses raw "HTTP error! status: NNN" strings into structured `APIError` objects; export `HTTP_ERROR_STATUS_RE` as a shared constant; map all HTTP 5xx to `NETWORK_ERROR` (retryable=true) to align with the retry loop; enhance all `USER_MESSAGES` entries to include actionable guidance
- `hooks/useStreamingAPI.ts` — All three `onError` callbacks now call `ErrorHandler.getUserMessage(ErrorHandler.fromRawMessage(error.message))` before storing in Redux, so users never see a raw HTTP error string; import shared `HTTP_ERROR_STATUS_RE` into `isRecoverableStreamError` instead of duplicating the pattern
- `components/ChatMessagesView.tsx` — Add optional `streamError` prop; the "no response" block shows the specific stream error message when available, and short-circuits its 1500ms display delay to 0ms when an error is already known
- `pages/ChatPage.tsx` — Pass `streamError={streamingState.error}` to `ChatMessagesView`; replace raw `{error}` display in the global error fallback with `ErrorHandler.fromRawMessage()` + friendly heading and "Try Again" label
- `components/ReconnectingBanner.tsx` — Replace "Stream dropped mid-response. Resuming from last received event." with "Your connection was interrupted — picking up where we left off."; replace "Attempt X/Y" with "Reconnection attempt X of Y"
- `components/InputForm.tsx` — Replace terse "Rate limited. Try again in Xs" with "You're sending messages too fast — please wait X second(s) before trying again."
- `utils/errorHandler.test.ts` — New: jargon-free gate (no HTTP status codes in any user message), actionable guidance gate, `fromRawMessage` mapping for all HTTP codes and network keyword patterns, `fromResponse` retryable assertions
- `components/__tests__/ErrorStates.test.tsx` — New: `ReconnectingBanner` copy tests (no technical jargon, attempt count format, mid-stream drop note), `InputForm` rate-limit alert copy tests (friendly text, correct pluralisation), `ChatMessagesView` no-response/stream-error state tests for all four error types plus loading guard
